# EppTools для Node.js — довідковий посібник

**Версія 1.1.1**

Це посібник для `@epptools/sdk`, EPP-клієнта для Node.js. Він відкриває TLS-сокет до реєстру на
порт 700, надсилає кадри команд RFC 5730–5734 і читає відповіді. У ньому немає ані фреймворку, ані
серверного коду: усе, що тут описано, — це клієнтська половина протоколу.

## Для кого це

Ви інтегруєте білінг або реєстрацію доменів із доменним реєстром, який говорить EPP, пишете
JavaScript чи TypeScript,
і ви новачок у EPP, але не в промисловому коді. Приклади з цих сторінок ви копіюватимете в програми,
які витрачають гроші, тож кожен приклад — це справді наявна команда зі справжніми аргументами, у
якій відповідь не лише надсилають, а й читають.

Словник тут — власний словник EPP: сесія, привітання, команда, відповідь, код відповіді, об'єкт,
розширення, черга poll. Там, де метод відповідає конкретній команді чи RFC, сторінка це називає, щоб
ви могли тримати відкритими поруч цей посібник і посібник реєстратора самого реєстру.

```bash
npm install @epptools/sdk
```

Потрібен Node.js 16 або новіший. Без залежностей. Типи TypeScript постачаються разом із пакетом.

## Дві домовленості, що діють усюди

**Дати повертаються власним рядком реєстру** — `2027-04-01T09:15:00Z`, ніколи не `Date`. Реєстр
вирішує, на який календарний день припадає продовження. Переформатування через місцевий часовий
пояс — це саме той шлях, яким клієнт зрештою показує попередній день і продовжує реєстрацію
відносно нього.

**Гроші повертаються точним десятковим рядком** — `'100.00'`, ніколи не числом. `0.1 + 0.2` у
двійковій рухомій комі не дорівнює `0.3`, і баланс, підсумований так, поступово розходиться.
Використовуйте бібліотеку десяткової арифметики або цілі числа в найменших одиницях валюти.

## Підтримка

Питання про бібліотеку, про кадр, який реєстр відхилив, або про помилку:
**https://github.com/epptools/node-sdk/issues**.

Наводьте `svTRID` із відповіді та `clTRID`, який надіслав ваш клієнт, — разом вони визначають точну
транзакцію в журналах реєстру, і саме це дає змогу відповісти на звернення без зустрічних запитань.
Надішліть і самі кадри, якщо можете, але спершу приберіть `<pw>`, `<newPW>` та `<authInfo>`: це живі
облікові дані, і бібліотека маскує їх у власних журналах із тієї самої причини.

Питання щодо облікового запису, оплат і реєстрації йдуть до вашого менеджера в реєстрі, а не сюди:
ця адреса — для клієнтської бібліотеки.
