# Хости

Об'єкти хостів (серверів імен) відповідають **RFC 5732**. Там, де реєстр використовує об'єкти
хостів, сервер імен має існувати як об'єкт, перш ніж на нього можна буде делегувати домен, — далі
домен посилається на нього за іменем. Про альтернативну модель, у якій glue-адреси їдуть усередині
доменної команди, див.
[Домени → Сервери імен](domains.md#сервери-імен-дві-моделі-які-ніколи-не-змішуються).

`client.host` містить по одному методу на кожну команду EPP. Кожен повертає `Promise<Response>`.

| Метод | Що йде в канал передачі |
|---|---|
| `check(names)` | `<check><host:check>` |
| `info(name)` | `<info><host:info>` |
| `create(name, addresses = [])` | `<create><host:create>` |
| `update(name, opts = {})` | `<update><host:update>` |
| `updateBuilder(name)` | той самий `<update>`, зібраний крок за кроком |
| `delete(name, force = false)` | `<delete><host:delete>` (+ `<registry:deleteNS>`) |

Перейменування **немає** — за задумом, а не через недогляд; див.
[Хост неможливо перейменувати](#хост-неможливо-перейменувати).

Кожен приклад нижче припускає підключений `client`, який уже виконав вхід, — див.
[Швидкий старт](quickstart.md). Таксономію винятків див. у [Помилках](errors.md), а використані
тут методи доступу — у [Відповідях](responses.md).

## Підпорядковані та зовнішні хости

Одна відмінність, яка керує кожною командою на цій сторінці:

| | Де живе | Glue-адреси |
|---|---|---|
| **Підпорядкований** | під доменом у зоні, яку обслуговує реєстр, напр. `ns1.example.com.ua` | **обов'язкові** — без жодної адреси create дає `2003` |
| **Зовнішній** | під доменом деінде, напр. `ns1.example.net` | **відхиляються** — його адреси живуть у власному реєстрі, тож надсилання адреси дає `2306` |

Клієнт, який завжди виводить адресу, отримає `2306` на кожному зовнішньому сервері імен, який
намагатиметься створити. Визначайте за іменем, а тоді надсилайте адреси або пропускайте їх.

---

## check

```js
check(names)   // => Promise<Response>
```

`avail` тут означає, що **ім'я вільне для створення об'єкта хоста**.

```js
const r = await client.host.check(['ns1.example.com.ua', 'ns2.example.com.ua']);

r.availability();                     // { 'ns1.example.com.ua': false, 'ns2.example.com.ua': true }
r.isAvailable('ns2.example.com.ua');  // true
r.unavailableReason('ns1.example.com.ua');   // 'in use' або null
```

**Коди відповіді:** `1000`.

---

## info

```js
info(name)   // => Promise<Response>
```

```js
const h = await client.host.info('ns1.example.com.ua');

h.objectName();      // 'ns1.example.com.ua'
h.roid();
h.statuses();        // ['ok'] або ['linked', 'clientUpdateProhibited', ...]
h.sponsor();         // clID
h.createdBy();       h.createdDate();
h.updatedBy();       h.updatedDate();

h.hostAddresses();
// [{ ip: '203.0.113.10', version: 'v4' }, { ip: '2001:db8::10', version: 'v6' }]
```

`hostAddresses()` повертає порожній список для зовнішнього хоста, і це правильна відповідь, а не
відсутня: glue-адреси несе лише хост усередині зони, яку обслуговує реєстр.

`version` береться з атрибута `ip` у каналі передачі й відкочується до `'v4'`, коли реєстр його
пропускає, — схема хоста це дозволяє.

Статус `linked` означає, що принаймні один домен усе ще делегує на цей хост, — саме через це
звичайне видалення завершується помилкою `2305`.

**Коди відповіді:** `1000`; `2303`.

---

## create

```js
create(name, addresses = [])   // => Promise<Response>
```

Адреси — це літерали IPv4 або IPv6 в одному плоскому списку. **Версію визначено за вас** і
записано в атрибут `ip`, тож вам не доводиться класифікувати їх самостійно й не вийде позначити
котрусь неправильно:

```js
const r = await client.host.create('ns1.example.com.ua', [
  '203.0.113.10',
  '2001:db8::10',
]);

r.code();          // 1000
r.objectName();    // 'ns1.example.com.ua'
r.createdDate();   // '2026-08-16T09:15:00Z' — власний рядок реєстру
```

Зовнішній хост створюється взагалі без адрес:

```js
await client.host.create('ns1.example.net');
```

Адреси мають бути публічними інтернет-адресами, і хост приймає щонайбільше 13 з них.

**Коди відповіді:** `1000`; `2001` (понад 13 адрес), `2003` (підпорядкований хост без адреси),
`2005` (некоректна адреса або ім'я), `2302` (хост уже існує), `2306` (адреса на зовнішньому
хості).

## update

```js
update(name, opts = {})   // => Promise<Response>
```

| Ключ | Тип | У каналі передачі |
|---|---|---|
| `addAddresses` | `string[]` | `<host:add>` з одним `<host:addr>` на кожен запис |
| `remAddresses` | `string[]` | `<host:rem>`, так само |
| `addStatuses` | `string[]` | `<host:add>` з одним `<host:status s="…">` на кожен запис |
| `remStatuses` | `string[]` | `<host:rem>`, так само |

Адреси й статуси, що йдуть в одному напрямі, поділяють один блок, а блок, у якому нічого немає, не
виводиться. IPv4 та IPv6 і тут розрізняються автоматично.

```js
// Перенумерувати сервер імен: додати нову адресу і прибрати стару однією командою, щоб
// хост ніколи не лишався без жодної.
await client.host.update('ns1.example.com.ua', {
  addAddresses: ['203.0.113.11'],
  remAddresses: ['203.0.113.10'],
});
```

Надсилайте принаймні одну зміну. Кадр, який не виражає жодної, доходить до реєстру як команда, що
нічого не просить, і повертається з `2003`.

Правило «підпорядкований / зовнішній» діє й тут: зовнішній хост не може отримати адреси (`2306`),
а підпорядкований не може лишитися без жодної (`2003`) — саме тому перенумерування вище додає й
видаляє в одній команді, а не у двох.

Встановлювати й знімати ви можете лише **клієнтські** статуси; `linked` та `ok` обчислює реєстр, а
статуси `server*` належать йому.

Оновлення не повертає нічого про об'єкт, тож перечитайте його через `info()`, коли вам потрібно
підтвердити результат, а не просто прийняття команди.

**Коди відповіді:** `1000`; `2001` (понад 13 адрес), `2003`, `2303`, `2304`, `2306`.

### Хост неможливо перейменувати

У цій бібліотеці немає перейменування, а передача `newName` кидає `ValidationError` ще до того, як
щось надіслано.

Це не прогалина в клієнті. Цей реєстр читає лише `<host:add>` та `<host:rem>`; блок `<host:chg>`
відкидається без жодного слова. Кадр, який несе і зміну адреси, і перейменування, застосував би
зміну адреси, відкинув би перейменування — і все одно відповів би `1000`, тож той, хто викликав,
дізнається про успіх команди, тоді як ім'я лишилося незмінним. Надіслане окремо перейменування не
несло б жодної зміни й дало б невиразний `2003`.

Відмова тут означає, що відповідь приходить із вашого власного коду, а її повідомлення називає і
проблему, і спосіб її розв'язати:

```js
// 1. Створити заміну.
await client.host.create('ns9.example.com.ua', ['203.0.113.10']);

// 2. Переспрямувати кожен домен, що використовує старий, — по одному domain:update на кожен.
for (const name of domainsUsingTheOldHost) {
  await client.domain.update(name, {
    add: { ns: ['ns9.example.com.ua'] },
    rem: { ns: ['ns1.example.com.ua'] },
  });
}

// 3. Видалити старий хост тепер, коли на нього вже ніщо не посилається.
await client.host.delete('ns1.example.com.ua');
```

Переспрямовуйте до видалення. Між кроком 1 і кроком 2 делеговані обидва хости, і це робочий стан;
видалення першим прибрало б сервер імен із кожної зони, яка його використовувала.

## updateBuilder

```js
updateBuilder(name)   // => HostUpdateBuilder
```

Та сама команда, зібрана по одному названому кроку за раз. `send()` викликає `update()`, тож кадр
ідентичний.

```js
await client.host.updateBuilder('ns1.example.com.ua')
  .addAddress('203.0.113.11')
  .remAddress('203.0.113.10')
  .addStatus('clientUpdateProhibited')
  .send();
```

Кожен списковий крок накопичує значення, нічого не надсилається до `send()`, і білдер надсилає
один раз. Див. [Білдери](builders.md).

## delete

```js
delete(name, force = false)   // => Promise<Response>
```

```js
await client.host.delete('ns1.example.com.ua');
```

**Хост, який усе ще є сервером імен для одного або кількох доменів, видалити неможливо** — реєстр
відповідає `2305` (асоціація об'єкта забороняє операцію), і це надходить як `ObjectStatusError`.
Спершу відкріпіть його від цих доменів, по одному [`domain.update()`](domains.md#update) на кожен
домен.

### Примусове видалення

`force: true` додає власне розширення реєстру `<registry:deleteNS confirm="yes"/>`, яке однією командою
прибирає хост із набору серверів імен **кожного** домену, що на нього посилався, а потім видаляє
його:

```js
const r = await client.host.delete('ns1.example.com.ua', true);
r.code();   // 1000 або 2400, якщо відкріплення не вдалося завершити
```

Усвідомлюйте, чого просите. Це змінює делегування доменів, яких ви не називали, а домен, у якого
лишилося менше серверів імен, ніж вимагає мінімум його зони, перестає резолвитися. Спершу
прочитайте зачеплені домени — `nameservers()` у кожній відповіді domain info скаже, хто
використовує хост, — і переделегуйте їх у те саме вікно обслуговування.

**Коди відповіді:** `1000`; `2303`, `2305` (усе ще використовується, для видалення без `force`),
`2400` (примусове відкріплення не вдалося завершити).
