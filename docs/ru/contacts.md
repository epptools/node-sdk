# Контакты

Объекты контактов следуют **RFC 5733**. Они идут первыми в любом сценарии подготовки услуг:
[домен](domains.md) ссылается на своего регистранта и ролевые контакты по идентификатору,
поэтому контакты должны существовать раньше домена.

`client.contact` несёт по одному методу на каждую команду EPP. Каждый возвращает
`Promise<Response>`.

| Метод | Что уходит на провод |
|---|---|
| `check(ids)` | `<check><contact:check>` |
| `info(id, authInfo = null)` | `<info><contact:info>` |
| `create(id, opts = {})` | `<create><contact:create>` |
| `createAuto(opts = {})` | тот же `<create>` под зарезервированным идентификатором |
| `createBuilder(id, email)` | тот же `<create>`, собираемый шаг за шагом |
| `update(id, opts = {})` | `<update><contact:update>` |
| `updateBuilder(id)` | тот же `<update>`, собираемый шаг за шагом |
| `delete(id)` | `<delete><contact:delete>` |
| `transfer(op, id, authInfo = null)` | `<transfer op="…"><contact:transfer>` |

Во всех примерах ниже предполагается подключённый `client` с выполненным входом — см.
[Быстрый старт](quickstart.md). Таксономия исключений — в [Ошибках](errors.md), а все
использованные здесь аксессоры — в [Ответах](responses.md).

## check

```js
check(ids)   // => Promise<Response>
```

Отправляет по одному `<contact:id>` на каждую запись. `avail` здесь означает, что **свободен
идентификатор**, а не что контакт существует: вы проверяете имя, которое хотите занять.

```js
const r = await client.contact.check(['C1', 'EXAMPLE-C2']);

r.availability();                  // { 'C1': false, 'EXAMPLE-C2': true }
r.isAvailable('EXAMPLE-C2');      // true
r.unavailableReason('C1');// 'in use' либо null
```

Если у вас нет собственной схемы именования, обойдите гонку «проверить, затем занять» целиком и
позвольте реестру сгенерировать идентификатор — см. [createAuto](#createauto).

**Коды ответа:** `1000`.

## info

```js
info(id, authInfo = null)   // => Promise<Response>
```

Как регистратор-владелец вы получаете полную запись. Для контакта, которым вы не владеете,
передайте его `authInfo`, чтобы увидеть полную запись вместо публичного подмножества.

```js
const c = await client.contact.info('C1');

c.objectName();     // 'C1' — ИДЕНТИФИКАТОР, а не имя человека
c.roid();
c.sponsor();        // clID
c.createdBy();      c.createdDate();
c.updatedBy();      c.updatedDate();
c.statuses();       // ['ok'] либо ['linked', 'clientUpdateProhibited', ...]

c.email();          // 'contact@example.com'
c.voice();          // '+380.441234567'
c.fax();            // null, если у контакта его нет
c.authInfo();       // код трансфера — никогда не пишите его в журнал

c.postalInfo();
// { int: { name: 'Ivan Petrenko', org: 'Pryklad LLC', street: ['vul. Khreshchatyk 1'],
//          city: 'Kyiv', sp: '', pc: '01001', cc: 'UA' },
//   loc: { name: 'Іван Петренко', ... } }

c.disclose();       // { flag: false, elements: ['email', 'voice'] } либо null
```

`postalInfo()` возвращает только те формы, которые реестр действительно прислал, разложенные по
форме; чаще всего у контакта она одна. Отсутствующие части приходят как `''`, а не как
отсутствующие ключи, поэтому шаблон может читать `.pc` без проверок.

Статус `linked` означает, что на контакт ссылается хотя бы один объект, — именно из-за этого
удаление падает с `2305`.

**Коды ответа:** `1000`; `2202` (неверный `authInfo` как не-владелец), `2303`.

## create

```js
create(id, opts = {})   // => Promise<Response>
```

| Ключ | Тип | На проводе |
|---|---|---|
| `name` | string | `<contact:name>` в единственном почтовом блоке |
| `org` | string | `<contact:org>`, отправляется только непустым |
| `street` | `string[]` | по одному `<contact:street>` на строку, до 3 |
| `city` | string | `<contact:city>` |
| `sp` | string | `<contact:sp>` (область / регион), отправляется только непустым |
| `pc` | string | `<contact:pc>` (почтовый индекс), отправляется только непустым |
| `cc` | string | `<contact:cc>` — двухбуквенный код страны |
| `type` | `'int'` \| `'loc'` | атрибут `type` этого блока; по умолчанию `'int'` |
| `postalInfos` | `PostalInfo[]` | по одному `<contact:postalInfo>` на запись — используйте это для обеих форм |
| `voice` | string | `<contact:voice>`, отправляется только непустым |
| `fax` | string | `<contact:fax>`, отправляется только непустым |
| `email` | string | `<contact:email>` — **обязателен** |
| `authInfo` | string | `<contact:authInfo><contact:pw>` |
| `disclose` | object | `<contact:disclose>` — см. [Раскрытие данных](#раскрытие-данных) |

Ключ, которого эта библиотека не знает, отклоняется ещё до сборки кадра, с указанием ближайшего
известного ключа. Ключ с опечаткой, который просто отбросили бы, всё равно получил бы в ответ
`1000` — без поля, которое вы собирались задать, и без единого признака этого в ответе.

`email` требуется по RFC 5733, поэтому пустое значение даёт `ValidationError` здесь, а не едет в
реестр, чтобы вернуться оттуда кодом `2003`.

`<contact:authInfo>` выводится всегда. Опустите ключ — и уйдёт пустой `<contact:pw/>`, который
просит реестр применить собственную политику.

### Две почтовые формы

Контакт несёт один или два блока `<contact:postalInfo>`, и разница между ними не косметическая:

| Форма | Письменность | Назначение |
|---|---|---|
| `int` | **только ASCII / латиница** | форма, которую реестр может предъявить любой стороне где угодно |
| `loc` | местная письменность, например кириллица | адрес в том виде, в каком его написал сам регистрант |

Кириллица в блоке `int` отклоняется с `2005`. Требуется хотя бы один блок; присылайте оба, если
у вас есть оба, — здесь ничего не отбрасывается, и `info` возвращает всё, что вы прислали.

Плоские ключи строят один блок. Для обеих форм используйте `postalInfos`:

```js
const r = await client.contact.create('C1', {
  postalInfos: [
    { type: 'int',
      name: 'Ivan Petrenko', org: 'Pryklad LLC',
      street: ['vul. Khreshchatyk 1'], city: 'Kyiv', pc: '01001', cc: 'UA' },
    { type: 'loc',
      name: 'Іван Петренко', org: 'ТОВ «Приклад»',
      street: ['вул. Хрещатик 1'], city: 'Київ', pc: '01001', cc: 'UA' },
  ],
  voice: '+380.441234567',
  email: 'contact@example.com',
  authInfo: 'C0ntact-Pw',
});

r.code();          // 1000
r.objectName();    // 'C1'
r.createdDate();   // '2026-08-16T09:15:00Z' — собственная строка реестра
```

Номера телефона и факса указываются в форме EPP `+CC.NNNNNNNNN`.

### Раскрытие данных
`disclose` — это переключатель приватности из RFC 5733. `flag` задаёт направление, а
перечисленные элементы — то, к чему оно применяется; ко всему, что **не** перечислено,
применяется противоположное обращение, поэтому без флага список не значит ничего.

```js
// Публиковать только адрес электронной почты и номер телефона.
disclose: { flag: false, addr: ['int', 'loc'], name: ['int', 'loc'], org: ['int', 'loc'] }

// Либо в другую сторону: вот это публиковать можно.
disclose: { flag: true, voice: true, email: true }
```

| Поле | Значение |
|---|---|
| `flag` | `true` = перечисленные элементы можно публиковать; `false` = их следует скрыть |
| `name`, `org`, `addr` | массив форм: `['int']`, `['loc']` или обе |
| `voice`, `fax`, `email` | `true`, чтобы перечислить элемент |

`name`, `org` и `addr` существуют по одному экземпляру на каждую почтовую форму, поэтому выбор
делается для каждой формы отдельно. Указав только `['int']`, вы оставите форму на местной
письменности публичной — настройка приватности, которая выглядит применённой, но таковой не
является.

Флаг читается по своему смыслу, а не по истинности с точки зрения JavaScript: `'0'`, `'false'` и
`''` приходят из HTML-форм и полезных нагрузок JSON, и все три в JS — истинные строки. Здесь они
означают **скрыть**, ровно так, как это написал вызывающий код.

Прочитать настройку обратно можно через `disclose()`, который возвращает `{ flag, elements }` с
суффиксом формы — `['name:int', 'name:loc', 'email']`.

**Коды ответа:** `1000`; `2003` (нет почтового блока или нет адреса электронной почты), `2005`
(неверный синтаксис — некорректный e-mail или кириллица в блоке `int`), `2302` (идентификатор
занят), `2306`.

## createAuto

```js
createAuto(opts = {})   // => Promise<Response>
Contact.AUTO_ID         // 'autonic' — зарезервированный идентификатор
```

Отправляет то же создание под зарезервированным идентификатором контакта, что просит реестр
**выбрать идентификатор** вместо вас. Сгенерированный идентификатор возвращается в ответе, и этот
ответ — единственное место, где он появляется:

```js
const r = await client.contact.createAuto({
  name: 'Pryklad LLC', city: 'Kyiv', cc: 'UA', email: 'contact@example.com',
});

const handle = r.objectName();   // 'c-9f4b2ad10e' — сохраните прямо сейчас
await saveContactHandle(handle);
```

Пользуйтесь этим, когда у вас нет собственной схемы именования и когда иначе вам пришлось бы
писать цикл повторов вокруг `2302`, потому что между вашим `check` и вашим `create` идентификатор
занял кто-то другой. **Каждый вызов создаёт новый идентификатор**, поэтому повтор — это второй
контакт, а не коллизия; из этого же следует, что слепой повтор после потерянного ответа оставит
вас с двумя контактами, а не с одним. Сверьтесь с собственными записями, прежде чем повторять.

Это значение — запрос, а не имя: оно не сохраняется как идентификатор, поэтому остаётся доступным
для всех. Если вы предпочитаете передавать его явно — например, через билдер, — оно
экспортируется константой:

```js
const { Contact } = require('@epptools/sdk');

await client.contact.createBuilder(Contact.AUTO_ID, 'contact@example.com')
  .internationalAddress({ name: 'Pryklad LLC', city: 'Kyiv', countryCode: 'UA' })
  .send();
```

**Коды ответа:** как у [create](#create), за вычетом `2302` — сталкиваться не с чем.

## createBuilder

```js
createBuilder(id, email)   // => ContactCreateBuilder
```

Та же команда, собираемая по одному именованному шагу. Идентификатор и адрес электронной почты —
аргументы, а не шаги, потому что реестр требует и то и другое, а шаг — это то, о чём можно
забыть. `send()` вызывает `create()`, поэтому кадр получается тот же самый.

```js
const r = await client.contact.createBuilder('C1', 'contact@example.com')
  .internationalAddress({
    name: 'Ivan Petrenko', org: 'Pryklad LLC',
    street: ['vul. Khreshchatyk 1'], city: 'Kyiv', postalCode: '01001', countryCode: 'UA',
  })
  .localizedAddress({
    name: 'Іван Петренко', city: 'Київ', countryCode: 'UA',
  })
  .voice('+380.441234567')
  .authInfo('C0ntact-Pw')
  .withhold('addr', 'voice')
  .send();
```

Каждый шаг описан в [Билдерах](builders.md).

## update

```js
update(id, opts = {})   // => Promise<Response>
```

| Ключ | Тип | На проводе |
|---|---|---|
| `addStatuses` | `string[]` | единственный `<contact:add>`, несущий по одному `<contact:status s="…">` на запись |
| `remStatuses` | `string[]` | единственный `<contact:rem>`, так же |
| `chg` | object | `<contact:chg>` — поля ниже |

`chg` принимает `postalInfo` (один блок), `postalInfos` (их массив), `voice`, `fax`, `email`,
`authInfo` и `disclose` и выводит их в порядке, зафиксированном RFC 5733.

```js
await client.contact.update('C1', {
  chg: { email: 'new-contact@example.com', voice: '+380.441234599' },
  addStatuses: ['clientUpdateProhibited'],
});
```

Устанавливать и снимать вы можете только **клиентские** статусы. `linked` и `ok` вычисляются
реестром, а статусы `server*` принадлежат ему.

### Правило частичного обновления: решает присутствие ключа

Внутри почтового блока вся инструкция состоит в том, **присутствует** ли ключ:

| Что вы пишете | Что происходит |
|---|---|
| ключ отсутствует | поле не отправляется, и реестр сохраняет то значение, которое хранит |
| ключ содержит значение | полю присваивается это значение |
| ключ содержит `''` | поле отправляется пустым, что **очищает** его |

Пустая строка — единственный способ убрать необязательное поле: `org`, `sp` или `pc`. Другого
написания для «удалить это» не существует.

```js
// Переселить контакт и убрать организацию, оставив имя и форму на местной письменности ровно
// такими, какие они есть.
await client.contact.update('C1', {
  chg: {
    postalInfo: { type: 'int', city: 'Lviv', cc: 'UA', street: ['vul. Svobody 1'], org: '' },
  },
});
```

**Адресный блок — это последовательность с обязательными городом и страной**, поэтому он
выводится целиком или не выводится вовсе. Тронете любую его часть — `street`, `city`, `sp`, `pc`,
`cc` — и уйдёт весь блок. Указывайте `city` и `cc` при каждом таком изменении: без них они уедут
в реестр пустыми элементами, а это очистит город у контакта, которому вы собирались лишь
поменять номер дома.

Имя и организация лежат вне этого блока, поэтому изменение одного лишь `name` отправляет одно
лишь `name`.

Изменение одной формы не трогает другую: `{ type: 'loc', … }` никогда не потревожит
международный блок.

### Для контакта нет clearAuthInfo

`chg.authInfo` **заменяет** код трансфера. RFC 5731 даёт домену форму с `null` для удаления кода;
RFC 5733 не определяет для контакта ничего подобного, поэтому код контакта можно заменить, но
нельзя удалить. Не пытайтесь подставить вместо этого пустой пароль: пустое значение — всё равно
значение, которое его держатель может предъявить.

**Коды ответа:** `1000`; `2303`, `2304`, `2306`.

## updateBuilder

```js
updateBuilder(id)   // => ContactUpdateBuilder
```

```js
await client.contact.updateBuilder('C1')
  .changeEmail('new-contact@example.com')
  .changeInternationalAddress({ city: 'Lviv', countryCode: 'UA', org: '' })
  .addStatus('clientUpdateProhibited')
  .send();
```

Действует то же правило присутствия: поле, которое вы не передали, не отправляется, а `''`
очищает. До `send()` в реестр не уходит ничего, и билдер отправляет один раз. См.
[Билдеры](builders.md).

## delete

```js
delete(id)   // => Promise<Response>
```

```js
await client.contact.delete('C1');
```

**Контакт, на который всё ещё ссылается домен, удалить нельзя** — реестр отвечает `2305`, и это
приходит как `ObjectStatusError`. Сначала отсоедините его: смените регистранта или ролевой
контакт домена через [`domain.update()`](domains.md#update), а затем удаляйте. `allContacts()` в
ответе на info домена скажет вам, какие идентификаторы домен ещё держит.

**Коды ответа:** `1000`; `2303`, `2305` (всё ещё связан).

## transfer

```js
transfer(op, id, authInfo = null)   // => Promise<Response>
```

`op` — одно из `'request'`, `'approve'`, `'reject'`, `'cancel'`, `'query'`. Трансфер контакта не
несёт ни периода, ни тарифа — только идентификатор и, для запроса, `authInfo` контакта.

| `op` | Кто отправляет | Действие |
|---|---|---|
| `request` | принимающий регистратор | запрашивает контакт, предъявляя его `authInfo` |
| `query` | любая из сторон | сообщает состояние ожидающего запроса |
| `approve` | текущий владелец | принимает его |
| `reject` | текущий владелец | отклоняет его |
| `cancel` | запрашивающая сторона | отзывает собственный запрос |

```js
const r = await client.contact.transfer('request', 'C1', 'the-code');

r.code();             // 1000 либо 1001, если операция завершается асинхронно
r.transferStatus();   // 'pending'
r.transfer();
// { status, requestedBy, requestedAt, actingClient, actBy, expiryDate }
```

Владелец узнаёт о запросе через [poll](poll.md) и отвечает `approve` или `reject`. `op="query"`
для контакта, у которого ничего не ожидает, даёт `2301`, а повторный `request` для того, у
которого запрос уже в ожидании, — `2300`.

**Коды ответа:** `1000` / `1001`; `2201` (не ваш), `2202` (неверный `authInfo`), `2300`, `2301`,
`2303`, `2304`.
