# Хосты

Объекты хостов (серверов имён) следуют **RFC 5732**. Там, где реестр использует объекты хостов,
сервер имён должен существовать как объект прежде, чем на него можно будет делегировать домен, —
дальше домен ссылается на него по имени. Об альтернативной модели, в которой glue-адреса едут
внутри доменной команды, см.
[Домены → Серверы имён](domains.md#серверы-имён-две-модели-которые-не-смешиваются).

`client.host` несёт по одному методу на каждую команду EPP. Каждый возвращает
`Promise<Response>`.

| Метод | Что уходит на провод |
|---|---|
| `check(names)` | `<check><host:check>` |
| `info(name)` | `<info><host:info>` |
| `create(name, addresses = [])` | `<create><host:create>` |
| `update(name, opts = {})` | `<update><host:update>` |
| `updateBuilder(name)` | тот же `<update>`, собираемый шаг за шагом |
| `delete(name, force = false)` | `<delete><host:delete>` (+ `<registry:deleteNS>`) |

Переименования **нет** — по замыслу, а не по недосмотру; см.
[Хост нельзя переименовать](#хост-нельзя-переименовать).

Во всех примерах ниже предполагается подключённый `client` с выполненным входом — см.
[Быстрый старт](quickstart.md). Таксономия исключений — в [Ошибках](errors.md), а
использованные здесь аксессоры — в [Ответах](responses.md).

## Подчинённые и внешние хосты

Единственное различие, которое управляет каждой командой на этой странице:

| | Живёт | Glue-адреса |
|---|---|---|
| **Подчинённый** | под доменом в зоне, которую обслуживает реестр, например `ns1.example.com.ua` | **обязательны** — без них создание даёт `2003` |
| **Внешний** | под доменом в другом месте, например `ns1.example.net` | **отклоняются** — его адреса живут в его собственном реестре, поэтому их отправка даёт `2306` |

Клиент, который всегда выводит адрес, получит `2306` на каждый внешний сервер имён, который
попытается создать. Определяйтесь по имени, а затем либо отправляйте адреса, либо опускайте их.

---

## check

```js
check(names)   // => Promise<Response>
```

`avail` здесь означает, что **имя свободно для создания объекта хоста**.

```js
const r = await client.host.check(['ns1.example.com.ua', 'ns2.example.com.ua']);

r.availability();                     // { 'ns1.example.com.ua': false, 'ns2.example.com.ua': true }
r.isAvailable('ns2.example.com.ua');  // true
r.unavailableReason('ns1.example.com.ua');   // 'in use' либо null
```

**Коды ответа:** `1000`.

## info

```js
info(name)   // => Promise<Response>
```

```js
const h = await client.host.info('ns1.example.com.ua');

h.objectName();      // 'ns1.example.com.ua'
h.roid();
h.statuses();        // ['ok'] либо ['linked', 'clientUpdateProhibited', ...]
h.sponsor();         // clID
h.createdBy();       h.createdDate();
h.updatedBy();       h.updatedDate();

h.hostAddresses();
// [{ ip: '203.0.113.10', version: 'v4' }, { ip: '2001:db8::10', version: 'v6' }]
```

`hostAddresses()` возвращает для внешнего хоста пустой список, и это правильный ответ, а не
пропавший: glue-адреса несёт только хост внутри зоны, которую обслуживает реестр.

`version` берётся из атрибута `ip` на проводе и откатывается к `'v4'`, когда реестр его
опускает, что схема хоста допускает.

Статус `linked` означает, что на этот хост всё ещё делегирован хотя бы один домен, — именно
из-за этого обычное удаление падает с `2305`.

**Коды ответа:** `1000`; `2303`.

## create

```js
create(name, addresses = [])   // => Promise<Response>
```

Адреса — это литералы IPv4 или IPv6 в одном плоском списке. **Версия определяется за вас** и
записывается в атрибут `ip`, поэтому вы никогда не классифицируете адреса сами и никогда не
подписываете их неверно:

```js
const r = await client.host.create('ns1.example.com.ua', [
  '203.0.113.10',
  '2001:db8::10',
]);

r.code();          // 1000
r.objectName();    // 'ns1.example.com.ua'
r.createdDate();   // '2026-08-16T09:15:00Z' — собственная строка реестра
```

Внешний хост создаётся вообще без адресов:

```js
await client.host.create('ns1.example.net');
```

Адреса должны быть публичными адресами Интернета, и у хоста их может быть не более 13.

**Коды ответа:** `1000`; `2001` (более 13 адресов), `2003` (подчинённый хост без адреса), `2005`
(некорректный адрес или имя), `2302` (хост уже существует), `2306` (адрес у внешнего хоста).

## update

```js
update(name, opts = {})   // => Promise<Response>
```

| Ключ | Тип | На проводе |
|---|---|---|
| `addAddresses` | `string[]` | `<host:add>` с одним `<host:addr>` на запись |
| `remAddresses` | `string[]` | `<host:rem>`, так же |
| `addStatuses` | `string[]` | `<host:add>` с одним `<host:status s="…">` на запись |
| `remStatuses` | `string[]` | `<host:rem>`, так же |

Адреса и статусы, идущие в одну сторону, делят один блок, а блок, в котором ничего нет, не
выводится. IPv4 и IPv6 и здесь различаются автоматически.

```js
// Сменить адрес сервера имён: добавить новый и убрать старый одной командой, чтобы хост ни на
// мгновение не остался без адреса.
await client.host.update('ns1.example.com.ua', {
  addAddresses: ['203.0.113.11'],
  remAddresses: ['203.0.113.10'],
});
```

Отправляйте хотя бы одно изменение. Кадр, который не выражает ни одного, доходит до реестра как
команда, ни о чём не просящая, и возвращается с `2003`.

Правило «подчинённый / внешний» действует и здесь: внешний хост не может получить адреса
(`2306`), а подчинённый не может остаться ни с одним (`2003`) — поэтому смена адреса выше
добавляет и удаляет в одной команде, а не в двух.

Устанавливать и снимать вы можете только **клиентские** статусы; `linked` и `ok` вычисляются
реестром, а статусы `server*` принадлежат ему.

Обновление не возвращает ничего об объекте, поэтому перечитайте его через `info()`, когда вам
нужно подтвердить результат, а не сам факт принятия команды.

**Коды ответа:** `1000`; `2001` (более 13 адресов), `2003`, `2303`, `2304`, `2306`.

### Хост нельзя переименовать
Переименования в этой библиотеке нет, и передача `newName` даёт `ValidationError` ещё до того,
как что-либо будет отправлено.

Это не пробел в клиенте. Этот реестр читает только `<host:add>` и `<host:rem>`; блок
`<host:chg>` отбрасывается без комментариев. Кадр, несущий и смену адреса, и переименование,
применил бы смену адреса, отбросил бы переименование — и всё равно ответил бы `1000`, так что
вызывающему сообщили бы об успехе команды, а имя осталось бы прежним. Переименование само по
себе не несло бы никакого изменения и получило бы невнятный `2003`.

Отказ здесь означает, что ответ приходит из вашего собственного кода, где сообщение называет и
проблему, и способ её решить:

```js
// 1. Создать замену.
await client.host.create('ns9.example.com.ua', ['203.0.113.10']);

// 2. Перенаправить каждый домен, который использует старый хост, — по одному domain:update.
for (const name of domainsUsingTheOldHost) {
  await client.domain.update(name, {
    add: { ns: ['ns9.example.com.ua'] },
    rem: { ns: ['ns1.example.com.ua'] },
  });
}

// 3. Удалить старый хост теперь, когда на него ничего не ссылается.
await client.host.delete('ns1.example.com.ua');
```

Перенаправляйте домены до удаления. Между шагом 1 и шагом 2 делегированы оба хоста, и это
рабочее состояние; удаление же первым шагом убрало бы сервер имён из каждой зоны, которая его
использовала.

## updateBuilder

```js
updateBuilder(name)   // => HostUpdateBuilder
```

Та же команда, собираемая по одному именованному шагу. `send()` вызывает `update()`, поэтому
кадр получается тот же самый.

```js
await client.host.updateBuilder('ns1.example.com.ua')
  .addAddress('203.0.113.11')
  .remAddress('203.0.113.10')
  .addStatus('clientUpdateProhibited')
  .send();
```

Каждый списочный шаг накапливается, до `send()` не отправляется ничего, и билдер отправляет один
раз. См. [Билдеры](builders.md).

## delete

```js
delete(name, force = false)   // => Promise<Response>
```

```js
await client.host.delete('ns1.example.com.ua');
```

**Хост, который всё ещё является сервером имён для одного или нескольких доменов, удалить
нельзя** — реестр отвечает `2305` (связь объекта запрещает операцию), и это приходит как
`ObjectStatusError`. Сначала отсоедините его от этих доменов, по одному
[`domain.update()`](domains.md#update) на домен.

### Принудительное удаление

`force: true` добавляет собственное расширение реестра `<registry:deleteNS confirm="yes"/>`, которое
убирает хост из набора серверов имён **каждого** домена, ссылавшегося на него, и затем удаляет
его — одной командой:

```js
const r = await client.host.delete('ns1.example.com.ua', true);
r.code();   // 1000 либо 2400, если отсоединение не удалось завершить
```

Понимайте, о чём просите. Это меняет делегирование доменов, которых вы не называли, а домен,
оставшийся ниже минимального числа серверов имён своей зоны, перестаёт разрешаться. Сначала
прочитайте затронутые домены — `nameservers()` в ответе на info каждого домена скажет, кто
использует хост, — и перенастройте делегирование в то же окно работ.

**Коды ответа:** `1000`; `2303`, `2305` (всё ещё используется, при удалении без `force`), `2400`
(принудительное отсоединение не удалось завершить).
