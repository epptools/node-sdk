# Ошибки

Каждый сбой, который поднимает эта библиотека, наследуется от **`EppError`**, поэтому один
`catch` покрывает всё, что она может бросить. Дальше отдельный класс существует там, где
различается правильный следующий шаг, — и больше нигде. Класса для «слегка иного оттенка того же
лекарства» нет, потому что таксономия, по которой нельзя действовать, — это лишь дополнительные
имена, которые надо выучить.

```js
const { EppError } = require('@epptools/sdk');

try {
  await client.domain.create('example.com.ua', { years: 1, registrant: 'C1' });
} catch (err) {
  if (err instanceof EppError) { /* что угодно из этой библиотеки */ }
  throw err;                    // всё остальное — ошибка в вашем собственном коде
}
```

## Иерархия

```
EppError
├── ConnectionError        транспорт: TLS, тайм-аут, кадрирование
├── ConfigError            этот клиент настроен неверно; каждый вызов падает одинаково
├── ValidationError        аргументы этого вызова неверны; ничего не отправлено
└── CommandError           реестр отказал (код >= 2000)
    ├── AuthError                  2200
    ├── InsufficientFundsError     2104
    ├── AuthorizationError         2201, 2202
    ├── ObjectExistsError          2302
    ├── ObjectDoesNotExistError    2303
    ├── ObjectStatusError          2304, 2305
    ├── PolicyError                2306, 2308
    └── SessionError               2500, 2501, 2502
```

| Что ловить | Когда поднимается | Коды | Что делать дальше |
|---|---|---|---|
| `ValidationError` | значение в **этом** вызове использовать нельзя; **ничего не отправлено** | — | исправьте аргументы. Следующий вызов может быть в полном порядке |
| `ConfigError` | неверно настроен сам клиент: нет хоста, нет учётных данных, тайм-аут в неверных единицах | — | исправьте развёртывание. До тех пор падает каждый вызов |
| `ConnectionError` | рукопожатие TLS, тайм-аут подключения или чтения, кадрирование, рассинхронизированный поток | — | соединение закрыто. Переподключитесь; для изменяющей команды сперва прочитайте [правило неизвестного исхода](#когда-невозможно-понять-произошло-ли-это) |
| `AuthError` | `login()` отклонён по учётным данным | `2200` | проверьте clID и пароль. Не зацикливайтесь: повторные неудачи приводят к блокировке адреса-источника |
| `InsufficientFundsError` | учётная запись не может оплатить эту операцию | `2104` | **остановите пакет**, пополните счёт, продолжите. Любая последующая тарифицируемая команда упадёт точно так же |
| `AuthorizationError` | объект существует, но он не ваш, либо `authInfo` неверен | `2201`, `2202` | не повторяйте с теми же данными. Получите правильный код трансфера — или примите, что объект не ваш |
| `ObjectExistsError` | уже зарегистрирован или уже занят | `2302` | имя ушло. `err.subject()` скажет, какое именно, если команда несла несколько |
| `ObjectDoesNotExistError` | нет такого домена, идентификатора или сервера имён | `2303` | устаревший идентификатор или опечатка. Перечитайте собственную запись, прежде чем повторять |
| `ObjectStatusError` | текущее состояние объекта запрещает операцию: `clientHold`, ожидающий трансфер, всё ещё связанный хост | `2304`, `2305` | снимите статус или связь, затем отправьте ту же команду снова |
| `PolicyError` | собственные правила реестра отказывают этому значению | `2306`, `2308` | менять нужно сам запрос. Повторять бессмысленно |
| `SessionError` | сервер завершает сессию | `2500`, `2501`, `2502` | переподключитесь, войдите заново и повторите команду — она могла быть совершенно правильной |
| `CommandError` | любой другой код ответа 2000 и выше | всё остальное | ветвитесь по `err.eppCode`; см. [Коды ответа](#коды-ответа) |

Отображение кода в класс решается в одном месте, поэтому расходиться между командами оно не
может.

## Плохой аргумент — не то же самое, что плохая конфигурация

`ValidationError` и `ConfigError` выглядят похоже, а требуют противоположных действий — поэтому
это разные классы, а не один.

**`ValidationError` — про этот вызов.** Что-то в аргументах использовать нельзя, и библиотека
отказала, не собирая кадр. Лечение — на стороне того, кто сформировал запрос; следующий вызов, с
другими аргументами, отработает нормально.

| Что поднимает | Пример |
|---|---|
| ключ опций, которого команда не знает | `secdns` вместо `secDNS`, с указанием ближайшего известного ключа |
| сумма тарифа, не являющаяся обычной десятичной строкой | `'100,00'`, `'$100'` |
| смешивание двух моделей серверов имён в одной команде | обычное имя рядом с именем, несущим glue-адреса |
| одновременная установка и очистка `authInfo` домена | схема не может выразить оба сразу |
| DS-запись без дайджеста, запись ключа без публичного ключа | |
| `removeAllDnssec()` рядом с поимённым удалением DNSSEC | в любом порядке |
| создание контакта без адреса электронной почты | RFC 5733 требует его |
| несуществующее поле для раскрытия | `'addres'` |
| переименование хоста | этот реестр игнорирует `<host:chg>`; см. [Хосты](hosts.md#хост-нельзя-переименовать) |
| запрос тарифа свыше [двадцати записей](balance.md#лимит-в-20-записей) | |
| повторная отправка билдера | см. [Билдеры](builders.md#билдер-отправляет-один-раз) |

**`ConfigError` — про развёртывание.** Клиент не может работать вообще, и каждый вызов будет
падать одинаково, пока кто-нибудь не изменит настройку. Это сигнал тому, кто эксплуатирует
сервис, а не ответ клиенту.

| Что поднимает | Пример |
|---|---|
| пустой `host` при `connect()` | |
| пустой `clid` или `password` при `login()` | сообщение говорит, чего именно из двух не хватает |
| пароль вне диапазона 6–128 символов | проверяется до открытия сокета |
| пароль длиннее 16 символов там, где сервер не предлагает RFC 8807 | ему некуда ехать; сервер ответил бы голым `2001` |
| `connectTimeout` или `readTimeout` меньше 1000 | это **миллисекунды**; значение, похожее на секунды, отвергается, а не поднимается тихо |

Последний пункт стоит того исключения, которое он поднимает. Прочитанный как миллисекунды,
`readTimeout: 30` — это тридцатая доля секунды: срок истекает, пока реестр ещё работает, команда
вполне может быть выполнена и оплачена, а тайм-аут чтения необратим — так что клиент отчитается о
сбое операции, которая на деле удалась. См. [Сессия](session.md#config).

```js
const { ValidationError, ConfigError } = require('@epptools/sdk');

try {
  await handleCustomerRequest(payload);
} catch (err) {
  if (err instanceof ValidationError) return reply(400, err.message);   // их входные данные
  if (err instanceof ConfigError) { pageTheOncall(err); return reply(503, 'temporarily unavailable'); }
  throw err;
}
```

## Сбои транспорта: `ConnectionError`

Всё, что лежит ниже EPP, приходит как `ConnectionError`: рукопожатие TLS, которое не удалось
проверить, тайм-аут подключения или чтения, кадр с невозможным префиксом длины, некорректный или
обрезанный ответ, ответ, чей `clTRID` не совпадает с отправленной командой.

В каждом из этих случаев соединение закрывается, и это сделано намеренно. Поток, у которого
съехали границы, выдал бы ответ на предыдущую команду при следующем чтении: `renew('example2.com.ua')`
вернул бы `1000` со сроком истечения `example1.com.ua`, оба домена были бы списаны, а ваши записи
неверны про оба. Закрытие обходится вам в переподключение; незакрытие — в правду.

Обрезанный кадр никогда не разбирается в частичный `Response`, поэтому наполовину доставленное
создание не может прочитаться как завершённая, оплаченная регистрация.

Самая частая ошибка при первом запуске — проверка сертификата, и лекарство от неё — в
[Сессии](session.md#когда-рукопожатие-не-проходит). Самая опасная — тайм-аут чтения **посреди
изменяющей команды**; см. [Когда невозможно понять, произошло ли
это](#когда-невозможно-понять-произошло-ли-это).

## Что отклонил реестр: `CommandError`

Любой код ответа 2000 и выше отклоняет промис самым конкретным классом для этого кода. Все они
несут одни и те же члены:

| Член | Тип | Что содержит |
|---|---|---|
| `err.eppCode` | number | код ответа EPP, например `2302` |
| `err.response` | `Response` \| `null` | полный разобранный ответ — на нём работает каждый [аксессор](responses.md) |
| `err.message` | string | `EPP 2302: Object exists ('example.com.ua')` — код, собственный текст реестра и объект, если реестр его назвал |
| `err.isRetryable()` | boolean | может ли повторная отправка той же команды сработать; см. [Повторные попытки](#повторные-попытки) |
| `err.subject()` | string \| `null` | объект, к которому реестр предъявил претензию, из первого `<extValue>` |
| `err.reasons()` | string[] | дополнительный диагностический текст, приложенный реестром |

```js
const { CommandError } = require('@epptools/sdk');

try {
  await client.domain.check(['example1.com.ua', 'b..com.ua', 'c.com.ua']);
} catch (err) {
  if (err instanceof CommandError) {
    err.eppCode;                       // 2005
    err.subject();                     // 'b..com.ua' — КАКОЕ из трёх
    err.reasons();                     // ['Invalid domain name syntax']
    err.response.extValues();          // то же самое, с элементом и его пространством имён
    err.response.svTRID();             // приведите его в обращении в поддержку
  }
}
```

`subject()` — это разница между «одно из этих трёх имён отклонено» и знанием, какое именно. В
команде, несущей несколько объектов, ответ и так лежит в отклике; этот метод его читает.

### `AuthError`

Поднимается `login()`, когда реестр отвечает `2200`: неверен clID или пароль. Сессия так и не
открылась.

Класс намеренно узок. Во входе могут отказать и потому, что учётная запись достигла лимита
сессий (`2502`), потому что сервер закрывается (`2501`), потому что объявленный вами сервис не
предлагается (`2307`), потому что это соединение уже вошло (`2002`), или из-за версии протокола
(`2100`) — каждый случай приходит своим классом со своим лекарством. Назвав их все сбоем
аутентификации, вы отправитесь менять пароль, который вообще не был причиной.

Не повторяйте `2200` в цикле. Повторяющиеся неудачи аутентификации с одного адреса — ровно то,
что средства защиты от вторжений созданы замечать.

### `InsufficientFundsError`

`2104`. С запросом всё в порядке: учётная запись не может его оплатить, и любая последующая
тарифицируемая команда упадёт так же, пока счёт не пополнят.

Это тот случай, на котором пакет нужно **останавливать**, а не пропускать. Цикл, который
относится к нему как к любой другой ошибке, перемелет оставшуюся тысячу имён, выдав тысячу
одинаковых сбоев, и похоронит единственный факт, который имел значение.

```js
if (err instanceof InsufficientFundsError) { alertBilling(err.message); break; }
```

Проверяйте счёт перед серией через [`client.balance()`](balance.md#перед-пакетом-операций) и помните, что
это снимок: из того же кошелька тратят и другие сессии.

### `AuthorizationError`

`2201` — объект принадлежит другому регистратору. `2202` — предъявленный `authInfo` не совпадает.
Никогда не повторяйте с теми же данными; в объекте ничего не изменится.

Для трансфера `2202` означает, что код, который дал вам клиент, неверен или был перевыпущен.
Запросите актуальный, а не гадайте.

### `ObjectExistsError`

`2302`. Имя, идентификатор или сервер имён уже зарегистрированы. Повтор не сделает их свободными.

Между `check`, сказавшим «доступно», и `create`, отвечающим `2302`, лежит настоящая гонка, а не
ошибка в вашем коде: кто-то другой зарегистрировал имя в промежутке. `err.subject()` назовёт то,
на котором произошло столкновение, если команда несла несколько.

### `ObjectDoesNotExistError`

`2303`. Обычно это устаревший идентификатор или опечатка: закэшированный идентификатор контакта,
домен, который с тех пор удалили. Перечитайте собственную запись, прежде чем повторять, и
относитесь к этому коду как к ответу на вопрос («существует ли это ещё?»), а не как к
неисправности.

### `ObjectStatusError`

`2304` — операцию запрещает собственный статус объекта, например `clientDeleteProhibited` при
удалении или `pendingTransfer`, блокирующий всё остальное. `2305` — её запрещает связь: хост,
который всё ещё используется доменом, контакт, на который всё ещё ссылаются, домен с
подчинёнными хостами.

Та же команда сработает, как только вы уберёте то, что её блокирует, — и это единственное
семейство, где «исправь и повтори» ровно то, что нужно.

### `PolicyError`

`2306` — правила реестра отказывают этому значению. `2308` — нарушение политики управления
данными. Команда сформирована верно, и отправлять её вам можно; реестр говорит «нет» именно
этому содержимому: номер лицензии в зоне, которая её не принимает, период, которого зона не
предлагает, glue-адрес у внешнего хоста.

Повторять бессмысленно, пока не изменится сам запрос. `err.reasons()` обычно говорит, что менять.

### `SessionError`

`2500`, `2501`, `2502`. Сервер завершает сессию — тайм-аут простоя, перезапуск, ваша учётная
запись на пределе числа сессий. Сама команда могла быть совершенно правильной.

Переподключитесь, войдите заново и отправьте её снова. Это один из немногих по-настоящему
повторяемых сбоев, и `isRetryable()` возвращает `true` для всех трёх кодов. Для `2502` добавьте
задержку: у учётной записи уже столько сессий, сколько ей разрешено, и стук в дверь её не
откроет.

## Повторные попытки
```js
err.isRetryable()   // => boolean
```

Истинно только для сбоев, которые про **момент**, а не про **запрос**:

| Код | Класс | Почему повтор может сработать |
|---|---|---|
| `2400` | `CommandError` | реестр не смог выполнить команду; сам запрос был в порядке |
| `2500` | `SessionError` | сессия завершилась; сначала переподключитесь |
| `2501` | `SessionError` | сервер закрывается; сначала переподключитесь |
| `2502` | `SessionError` | слишком много сессий; переподключитесь после задержки |

Для всего остального он намеренно `false`. Повтор `2302` не сделает имя свободным, повтор `2104`
его не оплатит, а повтор `2306` не изменит политику реестра. Цикл, который считает любой сбой
временным, превращает один отказ в бан по частоте запросов, — а против тарифицируемой команды
цикл, игнорирующий это различие, и есть тот путь, которым за домен платят дважды.

```js
if (err instanceof CommandError && !err.isRetryable()) throw err;   // повтор не поможет
```

Повторяйте с растущей задержкой — несколько сотен миллисекунд, затем секунда, затем две — и с
потолком по числу попыток. Для семейства `2500` перед повтором переподключитесь и войдите: старое
соединение уже пропало.

**`isRetryable()` ничего не говорит об изменяющей команде, исход которой вам неизвестен.** Это
другой вопрос, и у него есть собственное правило ниже.

## Как отключить выброс исключений

`client.throwOnFailure(false)` перестаёт отклонять промис на кодах ответа 2000 и выше, так что
`response.code()` вы читаете сами. Это переключатель на весь клиент; `login()` по-прежнему
отклоняется на результате, отличном от `1000`, а `poll.drain()` по-прежнему отклоняется на
ответе, который не несёт ни уведомления, ни пустой очереди. Полный размен описан в
[Командах](commands.md#throwonfailure).

С выключенным выбросом исключений ничто не заставляет вас смотреть на код. В этом и цена:
проигнорированный `response.code()` — это сбой, которого ваша программа никогда не заметит, тогда
как необработанное отклонение промиса — сбой, который не пропустишь.

## Коды ответа
Каждый код из RFC 5730, с константой `ResultCode`, которую библиотека для него экспортирует,
классом, которым он приходит, и тем, что делать. Ветвитесь по константе, а не по голому числу.

```js
const { ResultCode } = require('@epptools/sdk');
if (err.eppCode === ResultCode.OBJECT_EXISTS) { /* 2302 */ }
```

### Успех — 1xxx

| Код | Константа | Означает | Что делать |
|---|---|---|---|
| `1000` | `SUCCESS` | выполнено | продолжайте; объект в том состоянии, о котором вы просили |
| `1001` | `SUCCESS_PENDING` | принято, выполняется асинхронно | **не отправляйте повторно.** Сохраните `svTRID` и следите за [очередью poll](poll.md) в ожидании итога |
| `1300` | `SUCCESS_NO_MESSAGES` | очередь poll пуста | прекратите разбор |
| `1301` | `SUCCESS_ACK_TO_DEQUEUE` | poll-уведомление ожидает | прочитайте, обработайте, затем подтвердите |
| `1500` | `SUCCESS_END_SESSION` | logout принят | сервер закрывает соединение |

Ни один из них не отклоняет промис. Чаще всего спотыкаются о `1001`: это не сбой и не
завершённая операция, а повторная отправка команды «чтобы наверняка» — это тот самый путь,
которым домен регистрируется и оплачивается дважды.

### Протокол и синтаксис — 2000–2099

| Код | Константа | Класс | Означает | Что делать |
|---|---|---|---|---|
| `2000` | `UNKNOWN_COMMAND` | `CommandError` | сервер не знает этой команды | проверьте глагол; обычная причина — сырой кадр |
| `2001` | `COMMAND_SYNTAX_ERROR` | `CommandError` | кадр невалиден по схеме | он не называет поля, поэтому сверьте кадр со схемой; высокоуровневые методы такого не производят |
| `2002` | `COMMAND_USE_ERROR` | `CommandError` | команда не подходит к этому состоянию, например второй `login` | исправьте последовательность |
| `2003` | `REQUIRED_PARAMETER_MISSING` | `CommandError` | отсутствует что-то обязательное | сообщение называет это; сюда же попадает обновление, не выражающее никакого изменения |
| `2004` | `PARAMETER_VALUE_RANGE_ERROR` | `CommandError` | значение вне диапазона: период, которого зона не предлагает, либо [предельная сумма ниже реальной цены](balance.md#что-означает-отказ-с-кодом-2004) | ничего не списано. Перекотируйте и решите |
| `2005` | `PARAMETER_VALUE_SYNTAX_ERROR` | `CommandError` | значение некорректно: плохое доменное имя, плохой e-mail, кириллица в почтовом блоке `int` | исправьте значение |

### Нереализованное, использование, биллинг — 2100–2199

| Код | Константа | Класс | Означает | Что делать |
|---|---|---|---|---|
| `2100` | `UNIMPLEMENTED_PROTOCOL_VERSION` | `CommandError` | версия в `<login>` должна быть `1.0` | проблема конфигурации, а не данных |
| `2101` | `UNIMPLEMENTED_COMMAND` | `CommandError` | реестр не реализует эту команду | не стройте на ней логику |
| `2102` | `UNIMPLEMENTED_OPTION` | `CommandError` | неподдерживаемая опция входа, обычно `lang` | выберите язык, который предлагает приветствие |
| `2103` | `UNIMPLEMENTED_EXTENSION` | `CommandError` | расширение здесь не предлагается, например DNSSEC в зоне без него | отправьте команду без этого расширения |
| `2104` | `BILLING_FAILURE` | `InsufficientFundsError` | недостаточно средств | остановите пакет, пополните счёт, продолжите |
| `2105` | `NOT_ELIGIBLE_FOR_RENEWAL` | `CommandError` | `curExpDate` не совпадает либо домен сейчас нельзя продлить | перечитайте срок истечения через `info()` и используйте собственную строку реестра |
| `2106` | `NOT_ELIGIBLE_FOR_TRANSFER` | `CommandError` | домен нельзя перенести | обычно блокировка или недавняя регистрация; решает политика |

### Безопасность — 2200–2299

| Код | Константа | Класс | Означает | Что делать |
|---|---|---|---|---|
| `2200` | `AUTHENTICATION_ERROR` | `AuthError` | вход не удался | проверьте clID и пароль; не зацикливайтесь |
| `2201` | `AUTHORIZATION_ERROR` | `AuthorizationError` | объект не ваш | остановитесь; он чужой |
| `2202` | `INVALID_AUTHORIZATION` | `AuthorizationError` | `authInfo` неверен | получите актуальный код трансфера |

### Жизненный цикл объектов — 2300–2399

| Код | Константа | Класс | Означает | Что делать |
|---|---|---|---|---|
| `2300` | `OBJECT_PENDING_TRANSFER` | `CommandError` | трансфер уже в ожидании | ответьте на него `approve` / `reject` либо подождите |
| `2301` | `OBJECT_NOT_PENDING_TRANSFER` | `CommandError` | в ожидании нет ничего, на что можно ответить | для потерянного `request` это и есть ответ, что он не начинался |
| `2302` | `OBJECT_EXISTS` | `ObjectExistsError` | уже зарегистрирован | имя ушло |
| `2303` | `OBJECT_DOES_NOT_EXIST` | `ObjectDoesNotExistError` | такого объекта нет | устаревший идентификатор или опечатка |
| `2304` | `OBJECT_STATUS_PROHIBITS_OPERATION` | `ObjectStatusError` | статус запрещает операцию | снимите статус, повторите |
| `2305` | `OBJECT_ASSOCIATION_PROHIBITS_OPERATION` | `ObjectStatusError` | что-то ещё присоединено | отсоедините, повторите |
| `2306` | `PARAMETER_VALUE_POLICY_ERROR` | `PolicyError` | правила реестра отказывают этому значению | измените запрос |

### Сервер — 2400+

| Код | Константа | Класс | Повторяем | Означает |
|---|---|---|---|---|
| `2400` | `COMMAND_FAILED` | `CommandError` | да | реестр не смог выполнить корректно сформированную команду |
| `2500` | `COMMAND_FAILED_SERVER_CLOSING` | `SessionError` | да | то же самое, и сессия завершается |
| `2501` | `AUTHENTICATION_SERVER_CLOSING` | `SessionError` | да | сервер закрывает сессию |

где-то дал сбой, а записалось ли что-нибудь, не сказано. Считайте исход неизвестным.

## Когда невозможно понять, произошло ли это
Тайм-аут чтения, оборванное соединение или любой `ConnectionError` посреди `create`, `renew`,
`transfer`, `restore` или `delete` оставляют исход по-настоящему неизвестным: **реестр мог
выполнить команду и списать деньги ещё до того, как ответ был потерян.** Эта библиотека не может
различить эти случаи, и вы по ошибке тоже не сможете — потерянный ответ и не дошедшая команда
выглядят отсюда одинаково.

**Не отправляйте команду повторно просто так.** Слепой повтор — это тот путь, которым домен
регистрируется и оплачивается дважды: первая попытка удалась, ответ на неё погиб на обратном
пути, а вторая попытка либо регистрирует ещё один год срока, либо сталкивается с вашей же первой
попыткой. Списание реально в любом случае.

Вместо этого спросите реестр, как обстоят дела:

| Команда, которая сорвалась | Спросить | Повторять, только если |
|---|---|---|
| `domain.create` | `domain.info(name)` | ответ `2303` — домена не существует |
| `domain.renew` | `domain.info(name)` и прочитать `expiryDate()` | срок истечения всё ещё тот, с которого вы начали |
| `domain.transfer('request')` | `domain.transfer('query', name)` | ответ `2301` — в ожидании ничего нет |
| `domain.restore` | `domain.info(name)` и прочитать `rgpStatus()` | домен всё ещё в `redemptionPeriod` |
| `domain.delete` | `domain.info(name)` | домен всё ещё на месте, в прежнем состоянии |
| `contact.create` | `contact.info(id)` | ответ `2303` |
| `host.create` | `host.info(name)` | ответ `2303` |

```js
const { ConnectionError, ObjectDoesNotExistError } = require('@epptools/sdk');

async function createOnce(client, name, opts) {
  try {
    return await client.domain.create(name, opts);
  } catch (err) {
    if (!(err instanceof ConnectionError)) throw err;   // отказ — это ответ, а здесь ответа нет

    // Соединение пропало. Переподключитесь и спросите реестр, как обстоят дела.
    await client.connect();
    await client.login();
    try {
      const info = await client.domain.info(name);
      // Домен есть. Создание прошло, деньги списаны; запишите это и НЕ отправляйте снова.
      await recordRegistration(name, info.expiryDate(), info.createdDate());
      return info;
    } catch (probe) {
      if (probe instanceof ObjectDoesNotExistError) return client.domain.create(name, opts);
      throw probe;   // ясности по-прежнему нет — решает человек, а не цикл
    }
  }
}
```

Три вещи, которые стоит запомнить.

**`1001` — не неизвестный исход.** Это вполне определённый ответ: команда принята и выполняется
асинхронно. Сохраните её `svTRID`, следите за [очередью poll](poll.md) и сопоставьте уведомление
обратно по этому идентификатору. Повторная отправка — то же двойное списание, только окольным
путём.

**`contact.createAuto()` невозможно сверить по идентификатору**, потому что вы его не выбирали, а
каждый вызов создаёт новый. Слепой повтор после потерянного ответа оставит вас с двумя
контактами, а не с одним. Сверяйтесь по собственным записям — или используйте идентификатор,
выбранный вами, ровно затем, чтобы повтор столкнулся с `2302`, а не удался дважды.

**Сбой, исход которого вы не можете определить, заслуживает оператора, а не автоматической второй
попытки.** Поставьте его в очередь на разбор вместе с отправленным `clTRID` и объектом, о котором
шла речь. Это горстка ручных сверок в год против счёта, который никто не сможет объяснить.

## Пакет, который ведёт себя правильно

Всё вышесказанное — в той форме, которая большинству интеграций и нужна:

```js
const {
  CommandError, ConnectionError, InsufficientFundsError, ObjectExistsError,
} = require('@epptools/sdk');

const taken = [];
const retryLater = [];
const needsReview = [];

for (const name of namesToRegister) {
  try {
    await client.domain.createBuilder(name)
      .years(1).registrant('C1').maxFee(quotedFor(name), 'UAH')
      .send();
  } catch (err) {
    if (err instanceof InsufficientFundsError) {
      // Это проблема не имени, а учётной записи. Продолжив, вы получите тот же сбой для
      // каждого оставшегося имени.
      alertBilling(err.message);
      break;
    }
    if (err instanceof ObjectExistsError) { taken.push(err.subject() || name); continue; }
    if (err instanceof ConnectionError) { needsReview.push(name); break; }   // исход неизвестен
    if (err instanceof CommandError && !err.isRetryable()) throw err;        // повтор не поможет
    retryLater.push(name);
  }
}
```

Четыре ветки, четыре разных следующих шага — ровно столько классов иерархия для этой ситуации и
определяет. Всё, что провалится сквозь них, — это сбой, которого данный код не предусмотрел, и он
должен дойти до человека, а не быть проглоченным всеядным `catch`.
