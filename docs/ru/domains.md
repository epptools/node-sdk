# Домены

Объекты доменов следуют **RFC 5731**. К ним применимы четыре расширения: **RFC 5910** (DNSSEC),
**RFC 3915** (восстановление RGP), **RFC 8748** (тарифы) и собственное расширение реестра, если оно
у него есть.

`client.domain` несёт по одному методу на каждую команду EPP. Каждый возвращает `Promise<Response>`.

| Метод | Что уходит на провод |
|---|---|
| `check(names, fee = null, currency = null)` | `<check><domain:check>` (+ `<fee:check>`) |
| `info(name, authInfo = null, hosts = 'all')` | `<info><domain:info>` |
| `create(name, opts = {})` | `<create><domain:create>` |
| `createBuilder(name)` | тот же `<create>`, собираемый шаг за шагом |
| `update(name, opts = {})` | `<update><domain:update>` |
| `updateBuilder(name)` | тот же `<update>`, собираемый шаг за шагом |
| `delete(name)` | `<delete><domain:delete>` |
| `renew(name, curExpDate, years = 1, fee = null)` | `<renew><domain:renew>` |
| `transfer(op, name, authInfo = null, years = null, fee = null)` | `<transfer op="…"><domain:transfer>` |
| `restore(name, fee = null)` | `<update>`, несущий `<rgp:restore op="request"/>` |

Во всех примерах ниже предполагается подключённый `client` с выполненным входом — см.
[Быстрый старт](quickstart.md). Код ответа 2000 и выше по умолчанию отклоняет промис
типизированной ошибкой, поэтому примеры читают успешный путь; таксономия — в
[Ошибках](errors.md), а все использованные здесь аксессоры — в [Ответах](responses.md).

## check

```js
check(names, fee = null, currency = null)   // => Promise<Response>
```

Отправляет по одному `<domain:name>` на каждую запись внутри `<domain:check>`. `fee` и
`currency` добавляют в тот же кадр запрос цены по RFC 8748; эта половина описана в
[Балансе и ценах](balance.md#запрос-цены).

Имя, которое нельзя зарегистрировать, — это **не** ошибка. Оно возвращается с `avail="0"` и
причиной внутри ответа `1000`, поэтому читайте ответ, а не полагайтесь на отсутствие
исключения.

```js
const r = await client.domain.check(['example.com.ua', 'taken.com.ua']);

r.availability();
// { 'example.com.ua': true, 'taken.com.ua': false }

r.isAvailable('example.com.ua');        // true
r.unavailableReason('taken.com.ua');    // 'in use'

// null означает, что об этом имени в ответе не сказано ничего: опечатка в аргументе или имя,
// о котором реестр не отчитался. Это НЕ то же самое, что «занято», и, приняв null за false,
// вы пропустите регистрацию, которую собирались сделать.
r.isAvailable('never-asked.com.ua');    // null
```

`isAvailable()` и `unavailableReason()` сопоставляют имя без учёта регистра, поэтому имя,
которое вы перевели в верхний регистр по пути, всё равно найдёт свой ответ.

**Коды ответа:** `1000`. Некорректное имя даёт `2005`, а зона, которую реестр не
обслуживает, — `2307`. Запрос тарифа более чем на 20 записей отклоняется с `2306` — библиотека
останавливает его раньше ошибкой `ValidationError`, см.
[лимит на кадр](balance.md#лимит-в-20-записей).

## info

```js
info(name, authInfo = null, hosts = 'all')   // => Promise<Response>
```

Отправляет `<domain:info>` с `<domain:name hosts="…">`. Как регистратор-владелец вы получаете
полную запись; для домена, которым вы не владеете, передайте вторым аргументом его `authInfo`,
чтобы увидеть полную запись вместо публичного подмножества.

`hosts` выбирает, какие хосты перечислит ответ:

| Значение | Что перечисляет ответ |
|---|---|
| `'all'` (по умолчанию) | делегированные серверы имён и подчинённые хосты |
| `'del'` | только делегированные серверы имён |
| `'sub'` | только подчинённые хосты |
| `'none'` | ни те, ни другие |

```js
const d = await client.domain.info('example.com.ua');

d.objectName();        // 'example.com.ua'
d.roid();              // 'D1-EXAMPLE'
d.sponsor();           // 'EXAMPLE' — учётная запись, которой домен принадлежит сейчас
d.registrarOfRecord(); // идентификатор, который публикуют WHOIS/RDAP реестра, или null
d.createdBy();         // crID          d.createdDate();   // crDate
d.updatedBy();         // upID, null, если изменений не было ни разу
d.expiryDate();        // '2027-08-16T09:15:00Z' — собственная строка сервера
d.transferDate();      // когда домен в последний раз сменил владельца, или null

d.statuses();          // ['ok'] либо ['clientHold', 'clientTransferProhibited', ...]
d.registrant();        // 'C1'
d.contacts();          // { admin: ['C1'], tech: ['EXAMPLE-C2', 'EXAMPLE-C3'] }
d.techContacts();      // ['EXAMPLE-C2', 'EXAMPLE-C3']
d.contactsFor('billing');   // [], когда роль никем не занята, — это законный ответ
d.allContacts();       // все идентификаторы, включая регистранта, без повторов

d.nameservers();            // ['ns1.example.com.ua', 'ns2.example.com.ua']
d.nameserverAddresses();    // встроенные glue-адреса по именам; {} в реестре с объектами хостов
d.subordinateHosts();       // хосты, живущие ПОД этим доменом

d.isSigned();          // true, если пришли хоть какие-то данные DNSSEC
d.dsRecords();         // [{ keyTag, alg, digestType, digest }, ...]
d.keyRecords();        // [{ flags, protocol, alg, pubKey }, ...]
d.license();           // номер товарного знака или лицензии, либо null
d.authInfo();          // код трансфера — никогда не пишите его в журнал
```

Три вещи в этом ответе стоит учесть при построении логики намеренно.

**Домен в периоде выкупа по-прежнему сообщает `ok`.** Состояния выкупа не являются значениями
`<domain:status>`; они приходят в `<extension>` и возвращаются через `rgpStatus()`. Клиент,
читающий только `statuses()`, увидит обычный `ok` у домена, которому осталось несколько дней
до вычистки.

```js
if (d.rgpStatus().includes('redemptionPeriod')) {
  // Удалён, но ещё восстановим — см. restore() ниже.
}
```

**`inactive` — не ошибка.** Реестр вычисляет этот статус для домена, у которого слишком мало
серверов имён для делегирования, поэтому имя, только что созданное без `nameservers`, сообщает
именно его.

**Даты возвращаются собственной строкой реестра**, а не объектом `Date`. Календарный день, на
который попадёт продление, определяет реестр; переформатирование через локальный часовой пояс —
это ровно тот путь, которым клиент начинает показывать — и продлевать относительно — вчерашний
день.

Для домена, которым вы владеете как спонсор, ответ может нести также ваши действующие цены
продления и восстановления; читайте их через `prices()` и `priceChannel()`, описанные в
[Балансе и ценах](balance.md#подсказки-о-цене-в-domaininfo).

**Коды ответа:** `1000`; `2202` (неверный `authInfo` как не-владелец), `2303` (такого домена
нет).

## create

```js
create(name, opts = {})   // => Promise<Response>
```

Строит `<domain:create>`. Ниже перечислен каждый ключ опций; **ключ, которого эта библиотека не
знает, отклоняется ещё до сборки кадра**, с указанием ближайшего известного ключа. Этот размен
сделан намеренно: опечатка, которую просто отбросили бы, всё равно получила бы в ответ `1000` —
без той части, о которой вы просили, и без единого признака этого в ответе. `secdns` вместо
`secDNS` зарегистрирует домен неподписанным, и узнаете вы об этом уже в зоне.

| Ключ | Тип | На проводе |
|---|---|---|
| `years` | number | `<domain:period unit="y">`; опустите его — и реестр применит собственное значение по умолчанию |
| `registrant` | string | `<domain:registrant>` |
| `contacts` | `{ role: handle }` либо `{ role: [handles] }` | по одному `<domain:contact type="role">` на каждый идентификатор |
| `nameservers` | `string[]` либо `{ name, addresses }[]` | `<domain:ns>` — см. две модели ниже |
| `nameServers` | то же | принимаемое написание `nameservers` |
| `authInfo` | string | `<domain:authInfo><domain:pw>` |
| `license` | string | `<registry:create><registry:license>` — если ваш реестр его требует |
| `secDNS` | `{ dsData, keyData, maxSigLife }` | `<secDNS:create>` (RFC 5910) |
| `fee` | `'100.00'` либо `{ amount, currency }` | `<fee:create>` — предельная сумма, см. [Баланс и цены](balance.md#ограничение-суммы-которую-вы-согласны-заплатить) |

### Контакты: один идентификатор на роль или несколько

`contacts` принимает для каждой роли любую из двух форм. RFC 5731 допускает повторяющийся
`<domain:contact type="…">`, поэтому каждый идентификатор получает собственный элемент:

```js
contacts: { admin: 'C1', tech: ['EXAMPLE-C2', 'EXAMPLE-C3'] }
```

Идентификаторы обрезаются по краям, а пустой отбрасывается, а не отправляется пустым элементом.

### Серверы имён: две модели, которые не смешиваются
Сервер имён задаётся либо **именем** — ссылкой на [объект хоста](hosts.md), уже существующий в
реестре, — либо именем **со встроенными glue-адресами**. Уточните в своём реестре, какую модель
он принимает.

```js
// Объекты хостов, созданные заранее через client.host.create():
nameservers: ['ns1.example.com.ua', 'ns2.example.com.ua']

// Либо glue-адреса, встроенные рядом с именем:
nameservers: [
  { name: 'ns1.example.com.ua', addresses: ['203.0.113.1', '2001:db8::1'] },
  { name: 'ns2.example.com.ua', addresses: ['203.0.113.2'] },
]
```

IPv4 и IPv6 различаются автоматически, поэтому атрибут `ip` вы не пишете никогда.

RFC 5731 делает `<domain:ns>` выбором между двумя формами, поэтому одна команда использует одну
модель. Смешанный список даёт здесь `ValidationError`, а не голый `2001` из реестра, не
называющий ни одного поля.

### authInfo

`<domain:authInfo>` при создании обязателен, поэтому библиотека выводит его всегда. Задайте
собственный код трансфера — или опустите ключ, и уйдёт пустой `<domain:pw/>`, который просит
реестр применить собственную политику зоны и сгенерировать код. Любой, у кого есть это
значение, может увести домен к другому регистратору: обращайтесь с ним как с учётными данными,
держите его вне журналов и заявок и меняйте после того, как передали клиенту.

### Полное создание, с чтением ответа

```js
const created = await client.domain.create('example.com.ua', {
  years: 1,
  registrant: 'C1',
  contacts: { admin: 'C1', tech: ['EXAMPLE-C2', 'EXAMPLE-C3'] },
  nameservers: ['ns1.example.com.ua', 'ns2.example.com.ua'],
  authInfo: 'D0main-Pw',
});

created.code();          // 1000 либо 1001, если реестр выполняет операцию асинхронно
created.objectName();    // 'example.com.ua'
created.createdDate();   // '2026-08-16T09:15:00Z'
created.expiryDate();    // '2027-08-16T09:15:00Z' — собственная строка реестра
created.feeAmount();     // '100.00', если реестр отразил тариф, иначе null
created.feeCurrency();   // 'UAH'
created.svTRID();        // сохраните: именно по нему поддержка находит транзакцию

if (created.isPending()) {
  // 1001 означает «принято», а не «выполнено». Итог придёт позже poll-уведомлением, в paTRID
  // которого лежит ЭТОТ svTRID — сохраните его, иначе вы не поймёте, к какой из отложенных
  // операций относится уведомление. См. Poll.
  await recordPending(created.svTRID(), 'example.com.ua');
}
```

### DNSSEC при создании

```js
await client.domain.create('example.com.ua', {
  years: 1,
  registrant: 'C1',
  secDNS: {
    maxSigLife: 1209600,
    dsData: [{ keyTag: 12345, alg: 13, digestType: 2, digest: '49FD46E6C4B45C55D4AC' }],
  },
});
```

`secDNS` принимает `dsData`, `keyData` и `maxSigLife`. DS-запись может нести DNSKEY, из
которого она вычислена, — как `keyData` внутри записи. Реестр, который это принимает, сам
проверит дайджест по ключу, а тот, который не принимает, ответит `2306`, а не проигнорирует
лишний элемент:

```js
secDNS: {
  dsData: [{
    keyTag: 12345, alg: 13, digestType: 2, digest: '49FD46E6C4B45C55D4AC',
    keyData: { flags: 257, protocol: 3, alg: 13, pubKey: 'AwEAAb...' },
  }],
}
```

RFC 5910 требует в `<secDNS:create>` хотя бы одну запись, поэтому объект `secDNS`, в котором
нет ни `dsData`, ни `keyData`, не выводит блок расширения вовсе — вместо того чтобы вывести
недопустимый пустой.

### Лицензия при создании

Некоторые реестры не регистрируют отдельные имена без номера товарного знака или лицензии — чаще
всего это короткие и дорогие имена непосредственно под доменом верхнего уровня:

```js
await client.domain.create('example.com.ua', {
  years: 1, registrant: 'C1', license: 'TM-2026-000123',
});
```

Он едет в **собственном** расширении реестра, и его пространство имён клиент читает из `<greeting>` —
см. [Команды](commands.md#собственные-расширения-вашего-реестра). Реестру, который такого расширения
не объявляет, вместо кадра, который тот бы проигнорировал, будет брошено `ConfigError`.

Каким именно именам он нужен — это политика реестра, а не протокола, поэтому спрашивайте у своего.
О том, что вы не угадали, скажут два отказа: имя, которому лицензия нужна, но её не передали, обычно
получает `2003` (отсутствует обязательный параметр), а лицензия, отправленная туда, где её не ждут, —
`2306` (недопустимое значение параметра по политике).

**Коды ответа:** `1000`; `1001`, если поставлено в очередь; `2003` / `2004` / `2005` / `2306`
(валидация и политика), `2104` (недостаточно средств — см. [Баланс](balance.md)), `2302` (уже
зарегистрирован), `2103` (DNSSEC в этой зоне не предлагается), `2307` (зона не обслуживается),
`2004`, когда предельная сумма ниже реальной цены.

## createBuilder

```js
createBuilder(name)   // => DomainCreateBuilder
```

Та же команда, собираемая по одному именованному шагу. Собственного XML билдер не строит:
`send()` передаёт опции прямо в `create()`, поэтому кадр получается тот же самый и всё, что
проверяется для одного, проверяется и для другого. Меняется другое — опечатка становится
несуществующим методом, о чём вам скажет редактор.

```js
const response = await client.domain.createBuilder('example.com.ua')
  .years(1)
  .registrant('C1')
  .adminContact('C1')
  .techContact('EXAMPLE-C2').techContact('EXAMPLE-C3')   // накапливается
  .nameserver('ns1.example.com.ua').nameserver('ns2.example.com.ua')
  .authInfo('D0main-Pw')
  .maxFee('180.00', 'UAH')
  .send();
```

Каждый шаг описан в [Билдерах](builders.md).

## update

```js
update(name, opts = {})   // => Promise<Response>
```

Обновление в EPP — это **дельта**, а не замена. То, в какой блок попадает изменение, и есть вся
семантика команды:

| Блок | Ключи | Значение |
|---|---|---|
| `add` | `ns`, `contacts`, `statuses` | присоединить это, сохранив то, что уже есть |
| `rem` | `ns`, `contacts`, `statuses` | отсоединить ровно это |
| `chg` | `registrant`, `authInfo`, `clearAuthInfo` | заменить значение |

Рядом с ними — четыре ключа, которые едут в `<extension>`:

| Ключ | Тип | На проводе |
|---|---|---|
| `secDNS` | `{ add, rem, remAll, maxSigLife }` | `<secDNS:update>` (RFC 5910) |
| `restore` | `true` | `<rgp:update><rgp:restore op="request"/>` (RFC 3915) |
| `license` | string | `<registry:update><registry:license>` |
| `fee` | `'100.00'` либо `{ amount, currency }` | `<fee:update>` — предельная сумма |

`add.ns` и `rem.ns` принимают те же две модели серверов имён, что и `create`, с тем же запретом
смешивать их в одной команде.

```js
const r = await client.domain.update('example.com.ua', {
  add: { ns: ['ns3.example.com.ua'], statuses: ['clientTransferProhibited'] },
  rem: { ns: ['ns2.example.com.ua'] },
  chg: { registrant: 'EXAMPLE-C9', authInfo: 'N3w-D0main-Pw' },
});

r.code();        // 1000 либо 1001, если реестр выполняет операцию асинхронно
r.isPending();
```

Устанавливать и снимать вы можете только **клиентские** статусы: `clientHold`,
`clientDeleteProhibited`, `clientUpdateProhibited`, `clientTransferProhibited`,
`clientRenewProhibited`. Статусы `server*` принадлежат реестру, а `ok` и `inactive`
вычисляются — их не устанавливает никто.

Обновление не возвращает ничего об объекте, поэтому перечитайте его через `info()`, когда вам
нужно подтвердить результат, а не сам факт принятия команды.

### Отзыв утёкшего кода трансфера

`chg.clearAuthInfo: true` выводит `<domain:authInfo><domain:null/></domain:authInfo>`, который
**удаляет** код трансфера.

```js
await client.domain.update('example.com.ua', { chg: { clearAuthInfo: true } });
```

Это не то же самое, что задать пустой код. Пустой `<domain:pw/>` сохраняет пустую строку, а это
значение, которое его держатель по-прежнему может предъявить, так что домен остаётся ровно
настолько же уводимым, насколько был, — утечка не закрыта. Очищает код только форма с `null`.
Когда клиенту снова понадобится код, задайте новый через `chg.authInfo`.

Эти два ключа взаимно исключают друг друга: схема не может выразить оба сразу, и передача их
вместе даёт `ValidationError` ещё до того, как что-либо будет отправлено.

### DNSSEC при обновлении

Здесь обновление — тоже дельта, и форму создания оно не переиспользует:

| Ключ | Действие |
|---|---|
| `add` | `{ dsData: [...], keyData: [...] }` — добавить эти ключи |
| `rem` | `{ dsData: [...], keyData: [...] }` — удалить ровно эти; каждое поле должно совпасть с тем, что хранит реестр |
| `remAll: true` | удалить все ключи |
| `maxSigLife` | изменить время жизни подписи в секундах; может ехать отдельно |

```js
// Заменить весь набор ключей одной командой, без промежутка, когда домен остаётся неподписанным.
await client.domain.update('example.com.ua', {
  secDNS: {
    remAll: true,
    add: { dsData: [{ keyTag: 54321, alg: 13, digestType: 2, digest: 'A1B2C3D4E5F60718293A' }] },
  },
});
```

`remAll` и поимённый `rem` взаимно исключают друг друга. Объект `secDNS`, не выражающий никакого
изменения, не выводит блок `<secDNS:update>` вовсе, потому что пустой блок — это синтаксическая
ошибка в реестре (`2003`), а не «ничего не делать»: клиент, который строит блок безусловно, а
заполняет лишь иногда, будет падать именно в тех случаях, когда блок пуст.

**Коды ответа:** `1000`; `1001`, если поставлено в очередь; `2003` / `2004` / `2005` / `2306`,
`2303`, `2304` (статус запрещает операцию), `2305`.

## updateBuilder

```js
updateBuilder(name)   // => DomainUpdateBuilder
```

Билдер обновления называет блок, в который попадает каждое изменение, поэтому дельта видна прямо
в вызове:

```js
await client.domain.updateBuilder('example.com.ua')
  .addNameserver('ns3.example.com.ua')
  .remNameserver('ns2.example.com.ua')
  .addStatus('clientTransferProhibited')
  .changeRegistrant('EXAMPLE-C9')
  .clearAuthInfo()
  .send();
```

Ничего не отправляется до `send()`, и билдер отправляет один раз — повторный `send()`
отклоняется, потому что отправить дважды означало бы две команды, а для тарифицируемой команды —
два списания. См. [Билдеры](builders.md).

## delete

```js
delete(name)   // => Promise<Response>
```

```js
const r = await client.domain.delete('example.com.ua');
r.code();   // 1000 либо 1001, если поставлено в очередь
```

Домен, удалённый внутри окна add-grace, уходит немедленно. Иначе он переходит в
`redemptionPeriod` и может быть возвращён через [`restore()`](#restore) в течение окна
восстановления; после этого он переходит в `pendingDelete` и вычищается.

Подчинённые хосты блокируют удаление. Проверьте их заранее — ответ уже есть в прочитанном вами
`info()`:

```js
const d = await client.domain.info('example.com.ua');
if (d.subordinateHosts().length) {
  // Иначе 2305: они живут под доменом и должны уйти первыми.
}
```

**Коды ответа:** `1000`; `1001`, если поставлено в очередь; `2303`, `2304` (например, статус
`clientDeleteProhibited`), `2305` (что-то ещё присоединено).

## renew

```js
renew(name, curExpDate, years = 1, fee = null)   // => Promise<Response>
```

`curExpDate` должна равняться **текущей дате истечения срока** домена, и этот элемент — дата, а
не метка времени, а `info()` отдаёт срок истечения полной меткой времени. **Передавайте её как
есть:** дневную часть библиотека возьмёт сама.

Берётся она так, как её написал сервер, без разбора и без перевода часовых поясов. Это сделано
намеренно: отметки времени в EPP — в UTC, и дата истечения у реестра тоже в UTC, поэтому клиент,
который переформатирует её через местный пояс — а `new Date(...)` к этому и подталкивает, — для
каждого домена, истекающего около полуночи, попадает на сутки в ту или другую сторону и затем
продлевает по дате, которой у реестра нет. Переводите в местное время там, где показываете, а не
перед отправкой обратно.

```js
const d = await client.domain.info('example.com.ua');
const currentExpiry = d.expiryDate();            // '2027-08-16T09:15:00Z'

const r = await client.domain.renew('example.com.ua', currentExpiry, 1);   // уйдёт '2027-08-16'

r.objectName();    // 'example.com.ua'
r.expiryDate();    // НОВЫЙ срок истечения, ровно как его записал реестр
r.feeAmount();     // во сколько это обошлось, если реестр отразил тариф
```

Несовпадение `curExpDate` даёт `2105`, и это защита, а не помеха: она не даёт устаревшей записи
в вашей системе продлить домен, который уже продлён. Читайте текущий срок истечения
непосредственно перед продлением, а не из кэша.

Передайте `fee`, чтобы ограничить сумму, которую вы согласны заплатить, — см.
[Баланс и цены](balance.md#ограничение-суммы-которую-вы-согласны-заплатить).

**Коды ответа:** `1000`; `2004` (период вне диапазона), `2105` (несовпадение `curExpDate` либо
домен не подлежит продлению), `2104` (недостаточно средств), `2303`, `2304`, `2306`.

## transfer

```js
transfer(op, name, authInfo = null, years = null, fee = null)   // => Promise<Response>
```

`op` — одно из `'request'`, `'approve'`, `'reject'`, `'cancel'`, `'query'`, и оно становится
атрибутом `op` элемента `<transfer>`.

| `op` | Кто отправляет | Действие |
|---|---|---|
| `request` | принимающий регистратор | запрашивает домен, предъявляя его `authInfo` |
| `query` | любая из сторон | сообщает, на какой стадии запрос, ничего не меняя |
| `approve` | текущий владелец | принимает ожидающий запрос |
| `reject` | текущий владелец | отклоняет ожидающий запрос |
| `cancel` | запрашивающий регистратор | отзывает собственный запрос |

```js
const r = await client.domain.transfer('request', 'example.com.ua', 'the-code');

r.code();              // 1001 — принято, но не завершено
r.transferStatus();    // 'pending'
r.transfer();
// { status: 'pending',
//   requestedBy: 'EXAMPLE',    requestedAt: '2026-08-16T09:15:00Z',
//   actingClient: 'DELTA',   actBy:       '2026-08-21T09:15:00Z',
//   expiryDate: '2028-08-16T09:15:00Z' }
```

`actBy` — крайний срок, и он важен обеим сторонам: **молчание завершает трансфер.** После этого
момента реестр подтверждает трансфер, а не отменяет его, поэтому теряющий регистратор, который
подошьёт уведомление вместо ответа на него, лишится домена. Обе стороны узнают о каждом шаге
через [poll](poll.md), а пока установлен `pendingTransfer`, никакая другая операция с доменом не
принимается.

`years` отображается в `<domain:period>`, а принимает ли трансфер период вообще — это политика
реестра, а не протокола. Спросите у своего, как устроено у него:

- **Трансфер продлевает домен.** Он включает обязательное продление, тарифицируется и увеличивает
  срок регистрации. Передавайте число лет — обычно `1` — либо оставьте `years` равным `null`, чтобы
  опустить элемент и взять значение реестра по умолчанию. Значение, которого реестр не допускает,
  отклоняется с `2004`.
- **Трансфер только переносит домен.** Он бесплатен, и срок регистрации не меняется. Оставьте
  `years` равным `null`, чтобы `<domain:period>` не отправлялся вовсе.

Литеральный `0` — не способ сказать «никакой»: схемный тип элемента начинается с 1, поэтому кадр
будет отклонён как синтаксическая ошибка (`2001`) ещё до любой проверки политики. Сказать «никакой»
означает передать `null`.

Там, где зона не использует кодов авторизации, оставьте `authInfo` равным `null`, и никакой
`<domain:authInfo>` отправлен не будет.

Подтверждению, отклонению, отзыву и запросу состояния не нужны ни код, ни период:

```js
await client.domain.transfer('approve', 'example.com.ua');
await client.domain.transfer('reject',  'example.com.ua');
await client.domain.transfer('cancel',  'example.com.ua');

const q = await client.domain.transfer('query', 'example.com.ua');
q.transfer().actBy;    // сколько времени ещё остаётся у владельца
```

**Коды ответа:** `1000` / `1001`; `2201` (объект не ваш), `2202` (неверный `authInfo`), `2300`
(уже в ожидании), `2301` (в ожидании нет ничего, на что можно ответить), `2304`, `2306`, `2106`
(не подлежит трансферу), `2104` при тарифицируемом трансфере без средств.

## restore

```js
restore(name, fee = null)   // => Promise<Response>
```

Восстановление по RFC 3915. Это доменный `<update>`, всё содержимое которого —
`<rgp:restore op="request"/>`, и именно его строит метод: он вызывает `update()` с
`restore: true` и больше ни с чем, потому что никакие `add`, `rem` или `chg` восстановление
сопровождать не могут.

```js
const d = await client.domain.info('example.com.ua');

if (d.rgpStatus().includes('redemptionPeriod')) {
  const r = await client.domain.restore('example.com.ua', '1000.00');
  r.code();        // 1000 либо 1001, если восстановление завершается асинхронно
  r.feeAmount();   // во сколько обошлось восстановление
}
```

Второй аргумент — это максимум, который вы согласны заплатить, а не опубликованная цена.
Восстановление — одна из самых дорогих операций жизненного цикла, и предельная сумма — это
разница между отказом, который вы можете показать клиенту, и списанием, которое вам придётся
объяснять; см. [Баланс и цены](balance.md#ограничение-суммы-которую-вы-согласны-заплатить).

Восстановление работает только внутри окна восстановления. После него имя высвобождается, и
ответом будет то, что домена не существует.

**Коды ответа:** `1000` либо `1001`; `2104`, `2303`, `2304` (домен не находится в периоде
выкупа), `2306`.

## Когда изменяющая команда сорвалась и вы не знаете, выполнилась ли она

Тайм-аут чтения или оборванное соединение посреди `create`, `renew`, `transfer` или `restore`
оставляют исход по-настоящему неизвестным: реестр мог выполнить команду и списать деньги ещё до
того, как ответ был потерян.

**Не отправляйте команду повторно просто так.** Слепой повтор — это ровно тот путь, которым домен
регистрируется и оплачивается дважды. Вместо этого спросите реестр, как обстоят дела: `info()`
после создания, а после продления — сравните `expiryDate()` с тем, что вы ожидали. Повторяйте,
только если объект действительно находится в том состоянии, с которого вы начали. Полное правило
— в [Ошибках](errors.md).
